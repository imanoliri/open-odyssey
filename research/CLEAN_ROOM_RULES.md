# Clean-room and publication rules

These are conservative project rules, not legal advice.

## Private side

- Work only from a copy the researcher is legally entitled to use.
- Do not share disc images, BIOS files, executables, or extracted original assets.
- Keep raw captures, dumps, symbols, and disassembly outside the public project.
- Record facts, measurements, interfaces, and behavior in neutral language.

## Public side

- Write original source code without copying decompiled implementation.
- Use original or properly licensed models, textures, UI, writing, audio, and music.
- Use an original title, world, mission layouts, aircraft designs, and branding.
- Publish behavioral principles and measured ranges, not original content.
- Keep provenance and license records for every third-party asset.

## Review gate

Before publishing a feature or asset, answer:

1. Is it code or expressive content copied from the original?
2. Is it recognizably tied to the original name, story, level, art, or audio?
3. Can we explain its independent design source and asset license?
4. Would the feature still make sense in an original adventure-flight game?

If the answer is uncertain, keep it private pending review.
